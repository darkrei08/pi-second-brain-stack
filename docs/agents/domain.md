# Domain documentation

This is a single-context repository.

- Add `GLOSSARY.md` at the repository root when domain terms need explicit definitions.
- Add ADRs under `docs/adr/` when an architectural decision needs durable rationale.
- Before implementation, read relevant glossary entries and ADRs if they exist.
- Use the established terms `document`, `source`, `chunk`, `segment`, `embedding`, `entity`, `relationship`, `citation`, `retrieval`, and `provenance` consistently.
