# Contract and boundaries for the three repositories

## Ownership and direction

**Recommendation (not yet implemented):** `darkrei08/pi-second-brain-backend` owns the Node gateway, HTTP contract, migrations, storage, ingest command, and backend tests (`src/gateway-server.js`, `src/postgres-store.js`, `docker/postgres/init/`, `src/ingest-directory.js`, `test/`). `darkrei08/pi-second-brain-shell` owns the Open WebUI integration and its tests (`integrations/open-webui/`, `docs/shell-stack.md:32`). `darkrei08/pi-second-brain-stack` retains public architecture, operating instructions, ODD and issue decisions (`docs/development.md`, `docs/private-runtime.md`, `odd/`, `.scratch/`), and the reference composition/deployment wiring now in `compose.yaml`. These are proposed destinations, not observed repositories. The runtime direction is shell/ingest client -> gateway -> backend store/provider, never shell -> PostgreSQL; shell users/folders/conversations remain in the shell store and documents/segments/memberships in the gateway store (`docs/shell-stack.md:58-65`, `compose.yaml:47-75`). The gateway does not import the Python plugins; it imports backend seams (`src/gateway-server.js:4-7`); the plugins make HTTP requests (`integrations/open-webui/filters/gateway_retrieval.py:74-84`, `integrations/open-webui/pipes/gateway_research.py:74-84`). No shared runtime library, mirrored SQL model or fourth contract repository is needed.

**Release gate for every wire row below:** backend owns executable HTTP examples/negative cases at its existing `test/` boundary; shell CI checks out a *pinned backend contract release* (published fixtures or checkout of the backend's contract test/fixtures at a tag), starts that backend with disposable storage and runs the shell's actual Python HTTP clients against it. Also run the backend's contract tests against the *oldest shell release still supported* before a backend release. Pin both versions in this repository's reference stack and run a smoke test of that pair before publishing reference instructions. This gate is a proposal, not an existing CI check (`docs/development.md:19,128-134`, `compose.yaml:20-75`). A fixture snapshot alone cannot prove deployment/auth or folder propagation. For unused routes, backend tests plus a representative curl/JSON fixture are sufficient; shell need not implement clients for routes it does not use (`src/gateway-server.js:413-702`).

## HTTP wire contract

Verified common envelope: only `GET /healthz` and `GET /readyz` are unauthenticated; all other paths authenticate *before routing*. POST requires `Content-Type: application/json`, an object body, and at most 1 MiB by default; a caller-supplied top-level `owner_id` is refused. JSON replies have `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`. Unknown route is 404; wrong method is 405 with `Allow`. Owner identity comes from authentication, never a body field (`src/gateway-server.js:9,16,60-108,286-295,711-756`). Owner for every row: backend; consumers: shell only where named, otherwise operator/ingest clients described in `docs/development.md:72-126` and `docs/shell-attachment-ingest.md:3-19`. Breaking-change gate: the wire release gate above, including success, malformed input and owner isolation for each row.

## Errors, identity, scope and citations

**Errors — backend owner; shell/ingest/operator consumers.** JSON failure is `{error:{code,message}}`; after SSE headers, `data: {"error":{code,message}}` then end, without `[DONE]` (`src/gateway-error.js:10-27`, `src/gateway-server.js:778-795`). Stable observed pairs: `401 unauthorized` / `Authentication is required; provide a valid bearer token and try again.`; legacy mapped-user failure `403 unknown_identity` / `The caller identity is not mapped` (`src/gateway-auth.js:8-11,89-96`). `400 invalid_json` / `A JSON body is required` or `The body is not valid JSON`; `415 unsupported_media_type` / `Content-Type must be application/json`; `413 body_too_large` / `The body exceeds 1048576 bytes` with connection closed by default; `400 invalid_request` / field-specific message (and malformed seam `TypeError` message); `404 not_found` / `No such route` or `document not found for this owner`; `405 method_not_allowed` / `That method is not supported for this route` (`src/gateway-server.js:60-106,25-30,719-726,792-795`, `src/gateway-error.js:14-16`). `409 conflict` / `document belongs to a different owner`; `429 model_busy` / `The model is at capacity; retry the request shortly.`; `503 not_ready` / storage/provider-specific safe message; `503 answers_unavailable` / `No answer model is configured` or `The configured chat provider does not support streaming`; `504 model_timeout` and `502 model_failed` carry seam/provider messages, sanitized to `The model request timed out` or `The model request failed; retry the request, and contact the operator if it persists.` in streaming; `500 internal_error` / `The gateway encountered an internal error; retry the request, and contact the operator if it persists.` (`src/gateway-server.js:25-57,361-362,416-438,545-547,619-620`, `src/gateway-error.js:18-27`). **Compatibility recommendation:** assert codes/status and the two fixed auth/generic messages; do not branch on arbitrary field-specific or provider-derived message text. Existing Python plugins mask all gateway errors into generic local exceptions, whereas the ingest command displays `error.message` (`integrations/open-webui/filters/gateway_retrieval.py:83-86`, `integrations/open-webui/pipes/gateway_research.py:83-86`, `src/ingest-directory.js:119-125`). Gate with positive/negative contract fixtures, not message snapshots of provider errors.

**Authentication — backend owner; shell/operator consumers.** Present `Authorization: Bearer <token>`. Preferred `GATEWAY_PRINCIPALS` array maps each credential to one opaque `owner_id`; legacy `GATEWAY_TOKEN` + `GATEWAY_OWNER_ID` optionally maps `x-shell-user-id` through `GATEWAY_SHELL_USERS`. Missing/wrong tokens get the same 401; an unmapped legacy shell id gets 403. Client cannot choose owner in the body (`src/gateway-auth.js:6-10,23-99`, `src/gateway-config.js:55-73,76-148`, `src/gateway-server.js:104-108,711-716`). Filter and Pipe present both Bearer token from admin Valves and `x-shell-user-id` from `__user__.id`, require nonempty id and refuse non-loopback cleartext URLs/redirects (`integrations/open-webui/filters/gateway_retrieval.py:13-37,60-86`, `integrations/open-webui/pipes/gateway_research.py:11-35,60-86`). **Verified mismatch:** Compose gives Open WebUI a shared `GATEWAY_TOKEN` for its direct model connection while gateway uses `GATEWAY_PRINCIPALS` (`compose.yaml:27,59-62`, `.env.shell-stack.example:4-5`). A direct completion call has no proof of `x-shell-user-id` in this code and, with the example single principal, uses the one configured owner rather than per-shell-user isolation (`src/gateway-auth.js:71-81`, `compose.yaml:56-62`). Do not claim end-to-end per-user isolation until a live shell test verifies the identity forwarding for *all* routes. Gate two users/tokens, wrong credential, spoofed header/body and model connection identity against real shell plus backend.

**Folder/collection scope — backend owns authorization and membership; shell owns `folder_id` and its lifecycle.** Shell Filter reads `body.folder_id`, Pipe reads `__metadata__.folder_id`, sends `[folder_id]`; absent means owner-wide search (`integrations/open-webui/filters/gateway_retrieval.py:96-102`, `integrations/open-webui/pipes/gateway_research.py:92-97`, `docs/development.md:126`). ID syntax is `[A-Za-z0-9][A-Za-z0-9._~-]*`; duplicates collapse; `collection_ids` omitted means no collection filter, `[]` means no matches on retrieval, and unknown/foreign IDs stay scoped rather than broadening. SQL filters owner, active retention, and membership (`src/opaque-id.js:1`, `src/gateway-server.js:110-123`, `src/postgres-store.js:95-108,1048-1095`, `docs/development.md:72,126`). **Exception:** answer/research validation rejects `[]` on the way to answer generation (`src/answer-question.js:208-210`); do not normalize it to omitted. Ingest creates/reuses owned collections and replaces memberships; confirm adds, move replaces; citations survive a move because revalidation uses owner/hash/retention, not membership (`src/postgres-store.js:387-411,1018-1045`, `docs/development.md:72`). Gate no-folder/unknown/foreign/empty cases separately, plus a post-move citation round-trip; do not couple shell to collection tables.

**Citation wire shape — backend owner; Pipe/operator consumers.** Issued entry: `{document_id,segment_id,text,citation:{label,ref,confidence,source_hash,segment_hash,location,lineage}}`, with ref `[doc:<document_id>#seg<segment_index>]`, qualified SHA-256 hashes, and segment ID opaque to consumers (`src/citation-resolver.js:108-150`, `src/segment-document.js:175-214`). Pipe prints only `citation.label` and `citation.ref`, plus unresolved integer marker numbers and stale segment-id strings; it does not show `location`, hashes or provenance (`integrations/open-webui/pipes/gateway_research.py:102-139`, `src/answer-question.js:73-85,251-281`). Resolve accepts the documented subset of a returned entry and reports freshness (`src/postgres-store.js:224-255,1018-1045`). Gate issue/resolve/stale and Pipe render of valid/invalid shapes; do not make shell derive IDs, hashes or page links from SQL.

**Audit and operational logs — backend owner; operator/documentation consumer, not shell.** A provider call emits one `model_call` event via the gateway audit callback: `event,kind,route,owner_id,model_id,outcome,duration_ms` and optional nonnegative `prompt_tokens,completion_tokens`; CLI adds `provider_host` and writes JSONL to stdout. No question, evidence, answer or citation text belongs on that line. `429` and readiness probe have no provider-call event; CLI also emits `gateway_listening` to stdout; unexpected failures emit sanitized `gateway_unexpected_failure` with route and error_class to stderr (`src/gateway-server.js:375-410,416-438,759-775`, `src/gateway-cli.js:39-67`, `docs/development.md:74`). Gate metadata-only shape plus no-event cases in backend tests and a stdout/stderr smoke; audit is **not** a shell API or a DB table (`docs/shell-stack.md:58-65`, `docs/development.md:74`).

## Configuration and private data

**Backend-owned process variables, consumed by operator/reference Compose:** `DATABASE_URL` points at backend PostgreSQL; `GATEWAY_HOST` defaults to loopback `127.0.0.1`, `GATEWAY_PORT` to `8080`; `GATEWAY_MODEL_CONCURRENCY` defaults 3, accepts 1..64; `GATEWAY_MODEL_REQUESTS_PER_MINUTE` defaults 60, accepts 1..60000, per owner, fixed minute; `GATEWAY_PRINCIPALS` JSON token/owner array is mutually exclusive with `GATEWAY_TOKEN`, `GATEWAY_OWNER_ID`, `GATEWAY_SHELL_USERS` (legacy shared-token user->owner map). Config requires tokens of at least 32 characters; restart rotates credentials (`src/gateway-config.js:3-7,30-52,55-148`, `docs/development.md:40,72`). `ANSWER_BASE_URL` and `ANSWER_MODEL` enable answer provider/readiness; `ANSWER_API_KEY` is its credential; `ANSWER_ALLOWED_HOSTS` allowlists remote exact hostnames. `EMBEDDING_BASE_URL` enables embedder, `EMBEDDING_API_KEY` its credential, `EMBEDDING_ALLOWED_HOSTS` its remote host allowlist; loopback exempt, remote defaults denied (`src/gateway-cli.js:23-51`, `docs/development.md:59-74`). Gate bad/mutually-exclusive config and no-secret logs in backend CI, then reference Compose's env substitution in stack smoke.

**Shell-owned process/Valve inputs, consumed by shell and reference Compose:** plugin admin Valves `GATEWAY_URL` (loopback HTTP or HTTPS remotely) and `GATEWAY_TOKEN` (Bearer value), populated by `bootstrap.py` from shell process env; `__user__.id` and the two folder locations are Open WebUI runtime inputs, not environment variables (`integrations/open-webui/bootstrap.py:29-35`, `integrations/open-webui/filters/gateway_retrieval.py:33-37,60-64,88-102`, `integrations/open-webui/pipes/gateway_research.py:31-35,60-64,88-97`). The reference Compose also uses `POSTGRES_DB/USER/PASSWORD`, `WEBUI_SECRET_KEY`, `HOST`, `PORT`, `WEBUI_AUTH`, `ENABLE_FOLDERS`, `ENABLE_OPENAI_API`, `ENABLE_DIRECT_CONNECTIONS`, `ENABLE_OLLAMA_API`, `OPENAI_API_BASE_URLS`, `OPENAI_API_KEYS` and telemetry flags; those are *deployment/upstream shell settings*, not new gateway API fields (`compose.yaml:5-8,47-65`, `.env.shell-stack.example:1-11`). Gate a rendered config without secrets in logs, bootstrap with admin Valves, and live shell discovery; **assumption:** upstream Open WebUI preserves these settings on future versions, not guaranteed by these files (`docs/shell-stack.md:32,49-55`). The optional manual ingest CLI uses client-side `GATEWAY_URL` and `GATEWAY_TOKEN`; they are not server-side `GATEWAY_HOST/PORT` (`src/ingest-directory-cli.js:15-16`, `docs/shell-attachment-ingest.md:9-15`).

**Database is backend private business, not a fourth shared schema.** Migrations/SQL owned and applied by backend: `schema_migrations`, `vector`/`pg_trgm`, `documents`, `segments`, `segment_embeddings`, `embedding_models`, `collections`, `document_collections` (`docker/postgres/init/000-migrations.sql`, `docker/postgres/init/001-extensions.sql`, `docker/postgres/init/002-schema.sql`, `docker/postgres/init/003-segment-embeddings.sql`, `docker/postgres/init/004-embedding-models.sql`, `docker/postgres/init/005-collections.sql`). Shell has a separate Open WebUI SQLite volume; `bootstrap.py` writes **that** Function store (a version-specific upstream integration), not backend tables (`docs/shell-stack.md:58-65`, `integrations/open-webui/bootstrap.py:10-14,36-67`). Reference Compose mounts backend init files and runs `pnpm migrate` before gateway start (`compose.yaml:11-13,36-40`). Gate backend migration + restore/retrieval against an old volume and fresh DB before backend rollout, and shell bootstrap against the pinned Open WebUI version; backup before migration (`docs/private-runtime.md:42-62`). Shell must consume HTTP only; reference repo may describe the schema but must not maintain an independently versioned copy (`src/gateway-server.js:4-7`, `docs/private-runtime.md:44`).

## Drift risks, ranked by architectural impact

1. **Identity across the direct model path is not established.** Filter/Pipe send `x-shell-user-id`, direct OpenAI connection config supplies only shared API key; recommended principals map token to owner, not shell user. Verify before promising per-user isolation (`compose.yaml:27,59-62`, `src/gateway-auth.js:71-96`, `integrations/open-webui/filters/gateway_retrieval.py:78-81`).
2. **Folder scope propagation is an unverified upstream seam.** Filter and Pipe read different Open WebUI input locations; tests mock HTTP and do not load a real shell, and the docs explicitly say real `folder_id` propagation was not verified (`integrations/open-webui/filters/gateway_retrieval.py:96-102`, `integrations/open-webui/pipes/gateway_research.py:92-97`, `docs/development.md:128-134`). A missing folder yields owner-wide search, so require live no-folder vs selected-folder tests before release (`src/postgres-store.js:1048-1095`).
3. **HTTP shapes are code, not a single published machine-checkable contract.** Backend handlers expose additional suggest/confirm routes not in the listed route inventory (`src/gateway-server.js:485-535`, `docs/development.md:72`); Python clients check only selected response fields (`integrations/open-webui/filters/gateway_retrieval.py:103-114`, `integrations/open-webui/pipes/gateway_research.py:99-139`). Put canonical fixtures/tests in backend and pin them in shell CI rather than copying a hand-maintained OpenAPI file into each repo.
4. **Inconsistent empty collection scope can drift.** Retrieval accepts `[]` and returns no matches, but answer/research reject it; Filter/Pipe omit scope on absent folder (`src/postgres-store.js:95-108,1082-1090`, `src/answer-question.js:208-210`, `integrations/open-webui/filters/gateway_retrieval.py:96-102`). Preserve and test this distinction, or deliberately version a change.
5. **Bootstrap couples shell release to Open WebUI internals.** It writes SQLite `function` columns directly, while mounted Python files are not auto-loaded (`integrations/open-webui/bootstrap.py:10-14,36-67`, `docs/shell-stack.md:32`). Shell owns that adapter and its upstream-version test; backend and reference docs must not take a dependency on that table. The referenced upstream Function loader is <https://github.com/open-webui/open-webui/blob/v0.6.5/backend/open_webui/utils/plugin.py> (`docs/shell-stack.md:55`).
6. **Several wire details are implicit:** lexical response carries owner/retention/provenance and rank rather than a minimized public match DTO (`src/postgres-store.js:308-380`); confirm *adds* while move *replaces* (`src/postgres-store.js:932-970,886-919`); research rejects extra fields while answers accepts and ignores extras (`src/gateway-server.js:125-140,545-585`); a citation resolve validates `ref` presence but freshness uses hashes/owner/retention, not the ref or collection (`src/postgres-store.js:224-255,1018-1045`); SSE terminal failures have no metadata or `[DONE]` (`src/gateway-server.js:781-790`, `docs/development.md:104`). Assert those semantics in backend fixtures and shell integration where consumed rather than treating them as schema-table contracts.

7. **Shell HTTP policy is duplicated in both plugins.** URL validation, user-id extraction, bearer header and 10-second no-redirect client setup are copied, so a change to TLS, token handling or timeout can diverge (`integrations/open-webui/filters/gateway_retrieval.py:9-37,68-86`, `integrations/open-webui/pipes/gateway_research.py:8-35,68-86`). Shell owns both clients; test both with the same backend fixtures. Extract a shared helper only if Open WebUI Function loading supports sharing it; current bootstrap loads two standalone files (`integrations/open-webui/bootstrap.py:10-14,36-38`).

## Versioning and compatibility rule

**Recommendation:** backend tags a contract revision with every released gateway; keep existing `/v1` fields, auth and error codes working for the oldest supported shell release, allow additive optional fields that old clients can ignore, and treat changed defaults/scope, removal or renaming of fields/routes, changed required inputs, identity semantics or error codes as breaking changes requiring a new versioned endpoint or a coordinated shell release and pinned reference stack. Shell pins a tested backend contract revision; this reference repository records only the tested backend tag, shell tag and upstream Open WebUI tag, not a duplicate schema. The smallest automated enforcement is one backend-owned set of HTTP JSON/SSE/auth/scope fixtures exercised in backend CI and fetched by tag in shell CI to drive the real Python clients against a disposable backend, plus one paired-stack smoke in the reference repository. Existing CI and Python tests are local and mocked, so this gate is not yet verified (`docs/development.md:19,128-134`, `compose.yaml:20-75`).
